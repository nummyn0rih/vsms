Предкоммитное ревью задачи VSMS. Аргумент (может быть пустым): `$ARGUMENTS`

Работа идёт в двух потоках: два repo-агента считают в фоне, а ты в этом чате сверяешь дифф с чеклистом
ревью из спеки. Порядок шагов 1–2 обязателен — агенты уходят в фон ДО того, как ты начнёшь читать код,
иначе теряется весь смысл параллелизма.

Ты **ничего не правишь и не коммитишь**. Это ревью: находишь и докладываешь.

## Шаг 1 — срез изменений

Одним сообщением: `git status --short`, `git diff HEAD --stat`, `git log --oneline -5`
(последнее — чтобы предложить строку коммита в стиле репо).

Если рабочее дерево чистое и staged пусто — скажи об этом и остановись, ревьюить нечего.

## Шаг 2 — два агента в фон (одним сообщением, параллельно)

- `Agent(subagent_type: "invariant-review", run_in_background: true)` — «Проверь pending-изменения
  (`git diff HEAD` + `git diff --staged`) на соответствие инвариантам VSMS. Задача: `<task-id>`
  (или «спека не указана»). Верни находки в своём формате.»
- `Agent(subagent_type: "test-runner", run_in_background: true)` — «Прогони проверки VSMS: типы, линт,
  `prisma validate`, `prisma migrate status`. Только диагностика — ничего не чинить, миграции не запускать.»

**Не жди их.** Уведомления придут позже и попадут в отчёт шага 5. Пока они считают — иди на шаг 3.

## Шаг 3 — достать чеклист

Если пользователь уже вставил чеклист текстом — этот шаг пропусти, работай с его текстом.

Иначе ищи в `docs/prompts/` по аргументу, по порядку:

1. точное имя файла (с `.md` и без);
2. `PROMPTS-<ARG>.md`, в том числе в верхнем регистре;
3. `grep -rn "^### Чеклист ревью" docs/prompts/` → совпадение по суффиксу (case-insensitive);
4. подстрока в имени файла.

Из найденного файла вырежи:

- секцию `### Чеклист ревью <id>` — от заголовка до следующего `##`/`###`/`---`/конца файла;
- блоки `ОГРАНИЧЕНИЯ` и `ПРОВЕРКА (показать)` из ```text-блока того же под-промпта (они лежат ВЫШЕ чеклиста,
  внутри промпта). ОГРАНИЧЕНИЯ дают явные «нельзя», ПРОВЕРКА — готовые сценарии смоука.

Развилки:

- **Несколько секций «Чеклист ревью» в файле**, а аргумент их не различает (напр. `PROMPTS-C3.md` — C3a…C3d)
  → `AskUserQuestion` со списком найденных id. Не бери первую попавшуюся.
- **Аргумент пуст / файл не найден / секции нет** → не угадывай и не сочиняй пункты. Назови кандидатов,
  которые нашёл, попроси вставить чеклист текстом в чат и остановись. Агенты в это время досчитают.

## Шаг 4 — сверка по пунктам

Главная часть. По каждому пункту чеклиста:

- проверяй **по коду**: читай реальные файлы из диффа (Read/Grep). Текст промпта — это то, что задумывалось,
  а не то, что сделано; верить ему нельзя;
- вердикт: `✅` / `❌` / `⚠ MANUAL`;
- **обязательное доказательство**: `file:line` или процитированная строка. `❌` без доказательства не ставь;
  если проверить нечем — это `⚠`, а не `✅`;
- запретительные пункты ОГРАНИЧЕНИЙ («не трогать X», «не менять схему») проверяй грепом X по диффу —
  затронутый запрещённый файл сам по себе находка;
- пункт ссылается на verify-скрипт («`settlement-rbac-verify` зелёный») → прогони
  `npx tsx scripts/<name>-verify.ts` и отчитайся результатом. Скрипты пишут в dev-ветку Neon и чистят за
  собой — по правилу проекта dev-данные одноразовые, это штатно. **Прод-БД не трогать никогда**;
- браузерный смоук, визуал, «UI жив при навигации без F5», печатные формы → `⚠ MANUAL` плюс конкретный
  сценарий из блока ПРОВЕРКА, чтобы человеку не пришлось его выдумывать.

Ничего не чинить по ходу, даже мелочи: находка идёт в отчёт, решение — за пользователем.

## Шаг 5 — сводный отчёт

Собирается, когда пришли уведомления обоих агентов. Формат:

```
### Инварианты (invariant-review) — <чисто / N находок>
<находки как их вернул агент, самое серьёзное первым>

### Проверки (test-runner) — <зелено / что упало>

### Чеклист ревью <id> — N/M
1. ✅ <пункт> — `file:line`
2. ❌ <пункт> — <в чём расхождение> — `file:line`

### ⚠ На тебе (ручной смоук)
- <пункт> → <сценарий из блока ПРОВЕРКА>

### ВЕРДИКТ: ГОТОВО К КОММИТУ | ЕСТЬ БЛОКЕРЫ
```

Блокер — это `❌` пункт, находка `high` от invariant-review или красный test-runner. `⚠ MANUAL` блокером
не считается, но выносится явным списком: без него вердикт «готово» неполный.

- **Готово** → предложи строку коммита в стиле репо (`type(scope): суть — детали (task-id)`, по-русски).
  Коммит не делай — это решение пользователя.
- **Блокеры** → перечисли минимальные точечные фиксы и жди решения. Не разворачивай рефакторинг.
