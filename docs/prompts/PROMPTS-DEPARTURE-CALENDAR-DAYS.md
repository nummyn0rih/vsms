# PROMPTS — departure-calendar-days: отправление = −2 КАЛЕНДАРНЫХ дня

> **Дефект на проде:** прибытие в понедельник 27.07 → отправление 24.07 вместо 25.07 (то же со вторником).
> **Миграции НЕТ.** DOMAIN уже поправлен — читать BR-12 и BR-31 в новой редакции ПЕРЕД кодом.

## Причина

Отправление считается **вычитанием 2 РАБОЧИХ дней**: при шестидневке из понедельника это суббота → пятница,
воскресенье перепрыгивается. Правильное поведение — **2 календарных дня**.

**Рабочие дни завода (BR-11/BR-18) ограничивают ТОЛЬКО ПРИБЫТИЕ.** Машину грузит и отправляет фермер — завод
в этом не участвует, поэтому отправление может приходиться на любой день недели, включая выходной завода.
Ограничений перевозчика по дням в системе нет.

## Где расходится (проверено)

| Место | Сейчас |
|---|---|
| Форма создания, `ShipmentFormDialog.tsx:50–56` | `shiftDate(±2)` — **календарные** ✅ |
| Массовое создание, `server/shipments/actions.ts:268` | `subtractWorkdays(…, 2, cfg)` — **рабочие** ❌ |
| Доска, `server/board/board.ts:33` (`departureISO`) | `subtractWorkdays(…, 2, cfg)` — **рабочие** ❌ |
| Доска, drag, `server/board/actions.ts:90` | `subtractWorkdays(…, 2, cfg)` — **рабочие** ❌ |

То есть клиент и сервер уже считают по-разному — форма показывает одно, сохраняется другое.

⚠ **Тесты фиксируют НЕВЕРНОЕ поведение:** `server/shipments/workdays.test.ts:177` — «subtractWorkdays
перешагивает нерабочие дни (зима: понедельник −2 → четверг)». Сам `subtractWorkdays` остаётся правильной
функцией (он нужен там, где речь о заводе) — меняются её ПРИМЕНЕНИЯ к дате отправления.
