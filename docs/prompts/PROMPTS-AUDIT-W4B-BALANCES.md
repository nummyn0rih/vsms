# PROMPTS — audit-w4b: агрегация балансов в БД + гард алертов (П-13)

> Волна 4, часть B. **Миграции НЕТ, схема не меняется.** Меняется способ вычисления балансов: агрегация
> переезжает из JS в БД. Часть A (индексы + `@unique`) должна быть закрыта — индекс
> `StockMovement[source_doc_type, source_doc_id]` и прочие уже на месте.
>
> Прикрытие — 145 тестов волны 3 плюс **обязательный parity-скрипт** (см. ниже): баланс кормит решения о
> деньгах и остатках, «примерно так же» здесь не годится.

## Что именно оптимизируем (по факту кода)

`server/inventory/balances.ts` → `getTareBalances()` тянет **ВЕСЬ леджер** `kind=packaging`
(`findMany` без агрегации, 6 полей) и сворачивает его в JS в `Map` по ключу `loc:type:state`.
`getIngredientBalances()` — то же для ингредиентов. Леджер **append-only и не сворачивается никогда**
(откаты добавляют сторно-строки, а не удаляют оригиналы), значит объём растёт монотонно весь сезон.

Умножается это на самом горячем пути: `getActiveAlerts()` в `app/(app)/layout.tsx` зовёт **обе** агрегации на
**КАЖДУЮ** навигацию внутри `(app)` — не только на дашбордах остатков. В коде это честно помечено как принятая
цена V1.1; пришло время её снять.

## Решения (зафиксированы)

| Развилка | Выбор |
|---|---|
| Чем агрегировать | **`prisma.groupBy`, не `$queryRaw`.** Типобезопасно, `_sum` возвращает `Decimal` (важно: `quantity` — `Decimal(15,6)`), не плодит вторую точку сырого SQL |
| Как учесть два плеча движения | Каждое движение даёт **+qty** в `(to_location, item, to_state)` и **−qty** в `(from_location, item, from_state)`. Значит **две** `groupBy`-выборки (по `to_*` и по `from_*`) и слияние в тот же `Map`. Знаки и пропуск `null` — ровно как сейчас |
| Дублирование логики | **Одна функция агрегации** с необязательным фильтром по items (`aggregateStockCells`). Дашборд зовёт без фильтра, алерты — с фильтром по items из правил. НЕ заводить вторую реализацию свёртки |
| Гард алертов | `getActiveAlerts`: сначала правила; **0 правил → сразу нули, к балансам не ходим**. Самый дешёвый выигрыш на горячем пути |
| Транзит-сентинелы (−1/−2/−3) | Остаются полноценными локациями агрегации — их показывает UI («В пути»). Не отфильтровывать |
| **Кэш (`unstable_cache`/TTL)** | **НЕ вводим в этой волне.** Аудит предлагал, но после groupBy запрос возвращает десятки строк вместо тысяч — узкое место снимается без кэша. Кэш добавил бы стейл-баги в остатки (тихие и неприятные) ради выигрыша, которого уже не нужно. Вернуться, если после замера всё ещё медленно. `revalidateStockDashboards()` остаётся как есть |
