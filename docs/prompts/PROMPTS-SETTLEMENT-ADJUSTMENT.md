# PROMPTS — settlement-adjustment: корректировка расчёта с поставщиком (BR-33)

> Договорённость «по этому акту платим N% от факта» — оплата части нестандарта (иногда и брака) сверх принятого.
> **Качество не искажается:** проценты категорий и брака остаются как есть, аналитика качества их и считает.
> **Меняется только база денег.** DOMAIN уже обновлён: §1 (четыре базы веса) + **BR-33** — читать ПЕРЕД кодом.
>
> **ЕСТЬ МИГРАЦИЯ** (обсуждена и утверждена): `AcceptanceAct += settlement_percent Decimal(5,2)?`.
> Первая прод-миграция после запуска → по правилу CLAUDE.md перед применением на прод нужен `pg_dump`.

## Пример (эталон для проверки)

Огурцы, факт 6850 кг: 6–9 см 53,7% · 9–12 см 34,5% · >12 нестандарт 10,4% · брак 1,4%.

| Величина | Значение |
|---|---|
| принятый % | 53,7 + 34,5 = **88,2%** |
| принятый вес | 6850 × 0,882 = **6041,7 кг** |
| `settlement_percent` | **97,00** |
| доплата % | 97 − 88,2 = **8,8%** |
| доплата кг | 6850 × 0,088 = **602,8 кг** |
| **оплачиваемый вес** | **6644,5 кг** |
| разнос доплаты | 6–9: 53,7/88,2 = 60,88% → **367,0 кг**; 9–12: 39,12% → **235,8 кг** (каждая по цене СВОЕЙ строки) |
| выполнение объёма | считается от **6041,7**, доплата НЕ входит |

## Решения (зафиксированы)

| Развилка | Выбор |
|---|---|
| Что храним | **Итоговый %** (97), не дельту: остаётся верным при перевеске/правке категорий |
| Область | Разовая, на конкретный акт (не на контракт/сезон) |
| Цена доплаты | Пропорционально принятым категориям, по цене их `ContractLine`. Отдельной цены нет |
| Объём контракта | Доплата в тонны выполнения **НЕ идёт** — только деньги |
| Потолок | `принятый% ≤ settlement_percent ≤ 100`. Именно 100, а не `100 − брак%`: допускается договорённость, затрагивающая часть брака (коммерческое решение; статистику брака не меняет). Скидка (ниже принятого%) запрещена |
| RBAC | admin (деньги) |
| Хранить ли оплачиваемый вес | **НЕТ** — вычисляется, как и принятый (принцип «вычислять, не хранить») |
