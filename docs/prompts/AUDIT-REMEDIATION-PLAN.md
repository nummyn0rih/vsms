## Волна 0 — СЕЙЧАС, параллельно вводу данных (кода не касается) [Ivan]

Цель: сделать текущий ввод данных необратимо защищённым.

1. **Первый `pg_dump`** — сразу как введены справочники (фермеры/культуры/тара/ТК/водители/нормы):
   ```bash
   pg_dump '<прод-direct-URL>' -Fc -f vsms-prod-$(date +%F).dump
   ```
2. **Дальше — дамп в конце каждого дня ввода.** Хранить вне Neon, держать несколько поколений.
3. **Проверить восстановление** (не откладывать на «потом»): развернуть свежий дамп в проект `vsms-dev`
   и убедиться, что приложение поднимается на этих данных. Непроверенный бэкап — не бэкап.

**Критерий готовности волны:** есть дамп, который реально восстанавливался.

## Волна 2 — Auth-стек и CVE (окно + обязательный смоук)

Подтверждено `npm audit`: **2 critical, 8 high**. Critical — `@auth/core ≤0.41.2` (GHSA-xmf8-cvqr-rfgj и др.),
тянется через `next-auth 5.0.0-beta.31`. Отдельно — advisory Next (middleware/proxy bypass), а вся авторизация
зоны `(app)` висит именно на `proxy.ts`.

| # | Находка | Что делаем |
|---|---|---|
| 2.1 | **П-1** | Обновить `next-auth`/`@auth/core` до версии без critical-advisory |
| 2.2 | **П-2** | Обновить Next до патча из advisory (в пределах 16.x) |
| 2.3 | **П-4** (частично) | Задать `session.maxAge` разумным (напр. 8–12 ч вместо дефолтных 30 дней) |

**Порядок обязателен:** ветка от `dev` → `npm audit fix` (без `--force`) → прогнать локально → preview-деплой →
смоук на preview → только потом merge в `main`.
**Обязательный смоук после обновления:** логин/логаут, роль в сессии (`/api/auth/session` → `role: admin`),
RBAC-кнопки видны, редирект неавторизованного, все 4 статуса отгрузки, сохранение акта приёмки.
**Ожидаемый побочный эффект:** смена версий auth может разлогинить — не пугаться, зайти заново.
**Спека:** `PROMPTS-AUDIT-W2-DEPS.md`. **Отложено:** перечитывание `active`/`role` из БД в jwt-callback —
когда появится второй пользователь.
