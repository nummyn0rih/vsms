## 1. Строка контракта не подставляется в акт (дефект)

**Симптом:** если у фермера по одной культуре **несколько строк контракта**, при создании позиции отгрузки
пользователь выбирает нужную строку, но на приёмке в акте она оказывается непривязанной и её приходится
выбирать заново.

**Что известно по коду:** `ShipmentItem.contract_line_id` сохраняется при создании отгрузки и доезжает в
`getActContext` как `itemLineId` (`server/acceptance/act.ts:163`, комментарий в `schema.ts:97` прямо называет
его «дефолт принятых категорий»). В `AcceptanceActDialog` есть `defaultLineId` (~112–117) из
`context.itemLineId ?? context.autoLineId`. Значит механизм заложен, но для **calibre**-культур с несколькими
строками до селектов категорий не доходит: `itemLineId` там прокидывается отдельно (~201–203), а каждая
принятая категория имеет свой селект строки.

**Задача:** дефолт должен применяться к КАЖДОЙ принятой категории, если строка не выбрана явно.
Диагностику провести по коду, не угадывать: возможно, `autoLineId` заполняется только когда строка ровно одна.

**Правила, которые нельзя нарушить:** BR-7/BR-8 (валидация привязки на сервере), нестандарт по умолчанию
**без** строки (иначе двойной счёт с BR-33 — см. гард w5a). Дефолт — только для категорий `is_accepted = true`.

## 2. Недельный вид на /acceptance

Сейчас зоны — сплошной список. Добавить **переключатель вида** (как на ленте отгрузок): «Список | По неделям».
В недельном виде машины группируются по ISO-неделям со сворачиванием, прошлые недели свёрнуты по умолчанию.

Переиспользовать то, что уже есть у ленты (`WeekBlock`, `weekKey`, `formatWeekRange`, паттерн `?view=` в URL) —
**не изобретать вторую механику недель**. Состояние вида — в URL (`?view=`), как везде.

Группировать по **дате прибытия** машины (`arrival_date`) — та же ось, что у приёмки по смыслу.

---

## 3. Поиск: убрать № машины, добавить № акта и ТК

Сейчас `machineVisible` (`server/acceptance/board-filter.ts`) ищет по: коду машины, водителю, имени фермера,
названию культуры.

**Убрать:** поиск по `m.code` — номер машины на фронте нигде не показывается, это чисто БД-идентификатор.
**Добавить:** поиск по **номеру акта** (`actNumber` у позиций/принятых) и по **транспортной компании**
(`transportCompanyName`).

Итоговый набор: водитель · ТК · фермер · культура · № акта. Плейсхолдер поля обновить соответственно.

⚠ `filterBoard` покрыт юнит-тестами (`board-filter.test.ts`) — тесты на поиск обновить под новый набор,
а не удалять.
