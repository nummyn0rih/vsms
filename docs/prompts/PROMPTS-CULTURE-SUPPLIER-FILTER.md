# PROMPTS — culture-supplier-filter: мультивыбор поставщиков в профиле культуры

> Экран `/analytics/culture/[id]`. Сейчас профиль показывает культуру целиком; нужен фильтр по поставщикам,
> чтобы смотреть «эту культуру у этих фермеров». **Миграции НЕТ.** Формулы ядра не менять.

## Что фильтруется, а что нет (решение пользователя)

| Блок | Поведение при выбранных поставщиках |
|---|---|
| **KPI** | **Пересчитать** по выбранным |
| **% брака по неделям** | **Пересчитать** по выбранным |
| **Динамика приёмки по неделям** | Остаётся (можно не фильтровать), но **если пересчитывается — то целиком**: приёмка, по перевеске и плановый темп должны относиться к одному набору |
| **«По поставщикам»** | Показывать **только выбранных** |
| **«Калибр — доли категорий за сезон»** | **Пересчитать** по выбранным |

⚠ **Плановый темп (`WeeklyPlan`) по поставщикам не разбит** — план ведётся на культуру/неделю, не на фермера.
Поэтому при активном фильтре он либо остаётся общим (и это надо честно подписать), либо скрывается.
**Решение: оставить общим и пометить подписью** — «плановый темп (по культуре целиком)». Молча показывать
общий план рядом с отфильтрованным фактом нельзя: это ровно тот класс тихого расхождения, который уже дважды
кусал (двойной счёт нестандарта, «Принято» на карточке контракта).

   - «Динамика приёмки по неделям»: серии «приёмка» и «по перевеске» — по выбранным.

3) ПЛАНОВЫЙ ТЕМП:
   WeeklyPlan ведётся на культуру/неделю и по фермерам НЕ разбит. При активном фильтре оставить его ОБЩИМ
   и явно подписать в легенде: «плановый темп (по культуре целиком)». Скрывать нельзя молча, пересчитывать

   культуры в сезоне), либо оставить общей с пометкой. Выбранный вариант описать в отчёте.
