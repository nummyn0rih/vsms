# PROMPTS — contract-lines-diff: правка строк контракта ломается о Restrict + нет истории цены

> **Дефект на проде:** нельзя сохранить контракт, если добавляешь вторую строку той же культуры (и вообще любую
> правку контракта, у которого уже есть приёмка). **Плюс** в журнале изменений нет истории цены.
> Оба дефекта — одна причина. **Миграции НЕТ.**

## Причина (найдена по коду)

`server/contracts/lines.ts` → `persistContractLines` полностью пересоздаёт набор строк:

```
await tx.contractLine.deleteMany({ where: { contract_id: contractId } });
…
await tx.contractLine.createMany({ data });
```

В комментарии там прямо записано: «Если на удаляемую строку есть ShipmentItem/CalibreResult
(`onDelete: Restrict`), deleteMany бросит ошибку — ловим в action. **Сейчас ссылок нет.**»

**Ссылки появились.** С момента, когда приёмка начала проставлять `ShipmentItem.contract_line_id` и
`CalibreResult.contract_line_id`, любая правка контракта пытается удалить строку, на которую уже ссылаются
данные, и упирается в `Restrict`. Раньше добавление работало ровно потому, что данных не было.

Дубли культур тут ни при чём — BR-5 их разрешает, `refine` на уникальность в схеме нет (проверено).

**Второй дефект из того же места:** `persistContractLines` возвращает сводку `"N строк(а)"`, и action пишет
`field: "lines"` с `oldValue: null`. Значит по-строчных диффов в ChangeLog нет → **истории цены не существует**,
хотя CLAUDE.md правило 6 требует «ChangeLog на все правки цены». Спор с фермером о цене сейчас по системе
не разрешается.

## Решение

Перейти с «снести и создать заново» на **диф по строкам**:

| Случай | Действие |
|---|---|
| Строка есть в форме и в БД (совпал `id`) | `update` изменившихся полей + **ChangeLog по каждому изменённому полю** |
| Строка есть в форме, `id` нет | `create` + ChangeLog «строка добавлена» |
| Строка есть в БД, в форме её нет | `delete`, **но только если на неё нет ссылок**; иначе — понятная ошибка с именем культуры |

⚠ **Форма сейчас не передаёт `id` строки** (`contractLineSchema`: culture_id, label, volume_tons, price_per_kg).
Без `id` диф невозможен — его нужно добавить в схему и форму (опциональный: у новых строк отсутствует).
