# PROMPTS — w5a-weight-edit-FIX: правка фактического веса у принятой позиции

> Находка `invariant-review` после w5a (med). Нетто-гард закрыл один из двух триггеров, названных в спеке w5a;
> второй — **«пересчёт расхода при правке веса»** — достижим штатным UI уже сегодня.
> **Миграции НЕТ.**

## Дефект

- `server/acceptance/actions.ts:39–75` — `setActualWeight` не проверяет наличие `AcceptanceAct`: `requireRole` →
  zod → сразу `update`.
- `AcceptanceActDialog.tsx:409–423` — поле веса без `disabled`/`readOnly`, редактируется и после приёмки.

**Сценарий:** позиция принята → правишь фактический вес → сохраняешь. `act.id` не меняется, нетто расхода
ингредиентов ≠ 0 → нетто-гард (корректно!) пропускает применение → **движения расхода остаются по старому весу**.
Если акт после правки веса вообще не пересохранять — расхождение всё равно остаётся.

Ломается база из CLAUDE.md: «ингредиенты расходуются по ФАКТИЧЕСКОМУ весу». Леджер молча расходится с перевеской,
и это не видно ни на одном экране.

**Не регресс:** старый `count`-гард в том же сценарии вёл себя идентично. Коммит w5a лишь сделал проблему явной,
удалив комментарий «actual_weight у принятой позиции read-only» — правило, которое описывалось, но никогда не
было реализовано.

## Решение (зафиксировано)

**Запретить правку `actual_weight_kg` при наличии акта — на СЕРВЕРЕ.** Хочешь изменить вес — откати приёмку
позиции (`revertAct`), поправь, прими заново.

**Почему так, а не автосторно+переприменение:**

| | Запрет (выбрано) | Авто-пересчёт (отвергнуто) |
|---|---|---|
| Корректность леджера | По построению: путь отката уже существует, оттестирован и storn'ит расход через `revertActItemWithin` | Нужен НОВЫЙ путь мутации ингредиентного леджера, который сам обязан быть нетто-корректным и идемпотентным |
| Согласованность с проектом | Совпадает с BR-32: «правка позиций только в `planned`; прямая правка `sent`/`arrived` запрещена — десинхрон плеч». Здесь ровно тот же класс | Заводит исключение из этого правила |
| Видимость | Пользователь осознанно откатывает — действие в ChangeLog, ничего «молча» | Тихий пересчёт. Молчаливость нас уже подвела на двойном счёте BR-33 |
| Цена | Правка веса после приёмки редка; откат — секунды | Сложнее, риск в самом чувствительном месте |

Ограничение, которое надо принять: `revertAct` — admin-only. Пока пользователь один (он же admin) это не мешает.
**Если появятся операторы и правка веса окажется частой — вернуться к авто-пересчёту осознанно**, отдельной задачей.

### Чеклист ревью
1. `setActualWeight` отклоняет правку при существующем акте — на сервере, в одной транзакции с проверкой.
2. `saveAct` не даёт протащить изменённый вес мимо гарда; пересохранение без смены веса работает.
3. UI блокирует поле с понятной подсказкой; серверная проверка не зависит от UI.
4. Цикл откат → правка веса → повторная приёмка даёт расход по новому весу, нетто корректно.
5. Автосторно НЕ реализовано; нетто-гард, `computeSettlement`, `execution.ts` не тронуты.
6. Тесты/lint/tsc/build зелёные.
