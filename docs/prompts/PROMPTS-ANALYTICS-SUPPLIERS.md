# PROMPTS — analytics-suppliers: таблица «По поставщикам» на профиле культуры

> Экран `/analytics/culture/[id]`, блок «По поставщикам». Расширение колонок + **дефект в колонке «Доля в
> культуре»**. **Миграции НЕТ.** Формулы ядра (`computeAcceptedKg`, `computeSettlement`, `getContractExecution`)
> не переписываем — только собираем из них показатели.

## 1. Дефект «Доля в культуре»

**Симптом (пользователь):** доля не считается по поставщикам, показывается только итог 100%.

**Что видно по коду (не диагноз, а отправная точка):** сервер считает долю корректно —
`server/analytics/culture.ts:202` `sharePct = a.acceptedKg / acceptedKgTotal × 100` на каждого фермера,
и она без изменений прокидывается в UI (`:358`). Компонент `SupplierTable.tsx` рисует её построчно
(`:94` ширина бара нормируется на `maxShare`, `:99` текст `Math.round(r.sharePct)%`).

То есть по чтению кода функция выглядит рабочей → **сначала воспроизвести на реальных данных и найти реальную
причину**, не «чинить» наугад. Возможные направления: `acceptedKgTotal` собирается по более широкому набору
позиций, чем строки таблицы; расхождение между «broad»-агрегатом и scoped-выборкой (в коде уже есть пометка про
это на `:417`); либо колонка визуально схлопывается при близких значениях.

## 2. Новые колонки

Сейчас: Фермер · Принято, т · Выполнение · Брак · Доля в культуре.

Добавить: **Заявлено** (контрактный объём по строкам этой культуры), **К оплате** (оплачиваемый вес, BR-33),
**% по всем категориям калибра** — не только брак.

Итоговый набор колонок:

| Колонка | Источник |
|---|---|
| Фермер | как есть |
| Заявлено, т | `targetKg` строк контракта этой культуры (уже считается: `execByFarmer.targetKg`, `culture.ts:337–347`) |
| Принято, т | как есть (`acceptedKg`) |
| К оплате, т | оплачиваемый вес = принятый + доплата BR-33 (**деньги считаются от него**, DOMAIN §1) |
| Выполнение | как есть (`execPct`) |
| % категорий | доля КАЖДОЙ категории калибра у этого поставщика (включая брак и нестандарт), а не только брак |
| Доля в культуре | после починки |

**Как показывать «% категорий»:** у культуры их немного (у огурца 4). Рекомендую компактные чипы/мини-стек
в одной ячейке с подписями категорий, цвета — из канона; при `acceptance_type = simple` колонка вырождается
в «% брака» (как сейчас). Точную подачу выбрать по `DESIGN-SYSTEM.md`, ширину таблицы не разносить.
