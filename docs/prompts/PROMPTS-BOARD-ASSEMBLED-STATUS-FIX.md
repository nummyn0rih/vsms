# PROMPTS — board-assembled-status-FIX: сборные машины в планировщике не показывают статус

> **Симптом (прод):** в планировщике карточка **сборной** машины (позиции нескольких фермеров, BR-31) не
> показывает статус: нет бейджа «Прибыла»/«Принята», рамка остаётся нейтрально-серой. Одно-фермерская карточка
> в тех же статусах отображается корректно. Пользователь по планировщику не мог отличить принятую машину от
> плановой и заподозрил расхождение в деньгах.
>
> **Данные в порядке — проверено:** статус в БД корректный (`accepted`), лента и приёмка показывают верно,
> сервер отдаёт статус в карточку (`server/board/board.ts:171` → `status: fs.status`). Контрольный SQL по проду
> (принятые позиции без привязки к строке контракта) вернул **0 строк** → выполнение контрактов и деньги
> считаются правильно. Дефект **чисто презентационный**.
>
> **Подтверждено экспериментом пользователя:** две тестовые отгрузки, идентичные операции; различие ровно одно —
> число поставщиков в машине. Одно-фермерская корректна на всех стадиях, сборная — некорректна на всех.
>
> **Миграции НЕТ. Сервер, расчёты, БД — не трогаем.**

## Две причины (найдены по коду)

**1. JSX — `app/(app)/planner/_components/BoardView.tsx:398`.** Бейдж статуса на сборной карточке рендерится
**только** при `card.arrivalOnly`, а это `fs.status === "sent"` (`board/board.ts:180`). Для `planned`,
`arrived`, `accepted` ветка `else` показывает только даты и хват — бейджа нет вообще.

```
{card.arrivalOnly ? (<span className={`badge s-${card.status}`}>…</span>) : (<><Dates …/>{handle}</>)}
```

**2. CSS — `app/globals.css:931–934`.** У `.mcard` статусный цвет левой границы задан только для двух статусов:

```
.mcard { border-color: #dcdcdc; border-left-width: 3px; }
.mcard.s-planned { border-left-color: var(--hairline-strong); }
.mcard.s-sent    { border-left-color: var(--link); }
.mcard .card-strip { display: none; }   /* полоса статуса скрыта у сборных */
```

Правил `.mcard.s-arrived` / `.mcard.s-accepted` **нет** → граница остаётся дефолтной серой. Плюс `.card-strip`
(которым одно-фермерская карточка показывает статус, `globals.css:774–777`) у сборных скрыт.

Итого сборная карточка слепа к статусу на **обоих** слоях, и именно для `arrived`/`accepted`.

**Побочно:** на `sent` бейдж есть, но обрезается краем карточки (видно на скриншоте пользователя) — тесная
строка заголовка. Починить заодно.

## Решения (зафиксированы)

| Развилка | Выбор |
|---|---|
| Показывать ли статус на сборных | **Да, всегда и во всех статусах.** Сборная машина — такая же отгрузка со статусом; скрывать его нельзя (пользователь принимает решения по этому экрану) |
| Источник цветов | **Канон `status-fills`** из `DESIGN-SYSTEM.md`, те же значения, что у `.card.s-*` (`globals.css:774–777`): planned `#d9d9d9` · sent `var(--link)` · arrived `#f5a623` · accepted `#29bc9b`. **Не изобретать новые цвета** |
| Как именно красить | Дополнить `.mcard.s-*` (левая граница) до всех четырёх статусов. `.card-strip` у сборных оставить скрытым — левая граница это её роль у `.mcard` |
| Метка «Машина» | Сохранить: она отличает сборную карточку от одно-фермерской. Бейдж добавляется рядом, не вместо |
