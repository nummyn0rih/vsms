# PROMPTS — settlement-export: экспорты расчётного листа (печать · PDF · Excel)

> Закрываем последнее место, где пользователь выносит данные из системы вручную: расчётный лист (вкладка
> «Расчёты» карточки фермера) используется для разговора и сверки с фермером, а отдать его нечем.
> **Миграции НЕТ. Новых формул и второй агрегации НЕТ** — обе выгрузки строятся из уже посчитанного
> `FarmerSettlement`. PDF отдельной задачей не является: это браузерное «Сохранить как PDF» с печатного листа.
>
> Срез режется на ДВА промпта (1 промпт = 1 проверяемая единица):
> **A — печатный лист** `app/print/settlement/[farmerId]` · **B — экспорт Excel** (+ multi-sheet в общем хелпере).
> Порядок обязателен: B опирается на решения A (набор колонок, подписи, наследование периода).

---

## Решения (зафиксированы с пользователем)

| Развилка | Выбор | Причина |
|---|---|---|
| Детализация на печати | **Переключатель в URL `?detail=`**, по умолчанию `1` (партии развёрнуты). `?detail=0` — свод без партий | Лист нужен для разговора с фермером (кейс «7 партий выписывались в чат построчно»), но у фермера с десятком строк развёрнутый лист уходит на несколько страниц — нужна компактная версия |
| Excel | **Три листа в книге**: «Расчёт» (строки + партии) · «Без привязки» · «Ожидают приёмки» | Секции имеют разный набор колонок; плоский лист с колонкой «Уровень» смешал бы деньги с неоплачиваемым весом — ровно та путаница, ради устранения которой лист и делался |
| Точка SheetJS | Расширяем **существующий** `lib/xlsx-export.ts` до книги, `downloadXlsx` остаётся тонкой обёрткой | Инвариант «не плодить вторую точку SheetJS»; 3 экрана уже зовут `downloadXlsx` — их сигнатура не меняется |
| Источник данных | **`getFarmerSettlement`** как есть | Инвариант «печать/экспорт — тем же чистым фильтром, что экран»; вторая выборка = второй источник истины |
| Период | Наследуется **из нормализованного `data.period`**, не из сырого URL | `resolveSettlementPeriod` уже уронил битые значения в «сезон»; строя ссылку из сырого `?from=` мы протащили бы мусор на лист |

### Чеклист ревью — settlement-print

1. Данные — ровно `getFarmerSettlement`; второй выборки, второй агрегации и формул в page.tsx нет.
2. Числа листа сходятся с экраном и с карточкой контракта; `batch.position.*` нигде не суммируются.
3. Колонка «Доплата» появляется только при `notes.hasSurcharge`; суффиксы периода — `periodColumnSuffix`.
4. Два скоупа не перепутаны: деньги/веса — за период, «Заявлено»/«Выполнение» — за сезон.
5. `?detail=` разбирается без состояния; localStorage нет; период в ссылке взят из нормализованного `period`.
6. Секция «Без привязки» печатается в обоих режимах; пустые состояния объясняют, а не показывают нули.
7. Стили — в существующем `print.css`, PDF-библиотек нет, `@media print` поверх экранов нет.
8. Гард печатных роутов не ослаблен; lint/typecheck/test зелёные.
