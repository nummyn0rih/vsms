# PROMPTS — notranslate-FIX: снять триггер расширений-переводчиков

> **Контекст:** на проде расширение-переводчик инжектило `content.js` и переписывало DOM, что ломало гидратацию
> React (клиентские компоненты оставались в серверном состоянии — симптом: не рендерился UI под `RoleGate`).
> Устойчивость уже повышена `session-hydration-FIX` (сессия приходит с сервера → RBAC-UI есть в серверном HTML).
> Этот срез убирает **саму причину срабатывания** переводчика.
>
> **Корень:** `app/layout.tsx` объявляет `<html lang="en">`, тогда как весь интерфейс — русский. Для браузера и
> расширений это «английская страница» с не-английским текстом при `uiLanguage=ru` → авто-перевод напрашивается.
>
> **Миграция:** НЕТ. Только корневой layout + metadata.

## Решения (зафиксированы)

| Развилка | Выбор |
|---|---|
| `lang` | **`ru`** — фактический язык интерфейса. Это ещё и корректность: скринридеры, переносы, поиск. |
| Сигнал «не переводить» | `translate="no"` на `<html>` + класс `notranslate` + `<meta name="google" content="notranslate">`. Уважается Google Translate и большинством расширений. |
| Гарантии | Полной гарантии нет — расширения подконтрольны пользователю. Цель: снять авто-триггер и не мешать тем, кто переведёт вручную. |
| Что НЕ делаем | Не глушим симптом через `suppressHydrationWarning` (он прячет предупреждение, а не чинит рассинхрон) и не пытаемся детектить/блокировать расширения скриптами. |

## Организационная часть (не код)

Технические сигналы снижают вероятность, но не отменяют контроль пользователя над браузером. Для рабочих машин:

- **Отключить переводчик на домене приложения** (в большинстве расширений есть «никогда не переводить этот сайт»).
- Для операторов, когда появятся: рабочий профиль браузера без лишних расширений — самый надёжный вариант.
- В инструкции для пользователей добавить строку: «интерфейс русский, автоперевод отключить».
