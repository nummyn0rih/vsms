# PROMPTS — settlement-sheet: расчётный лист по фермеру (экран)

> Фича №2 из Этапа 9 аудита. Единый лист «за что и сколько платим фермеру» — сейчас пользователь собирает его
> вручную (реальный кейс: 7 партий Тертышникова выписывались в чат построчно).
> **Миграции НЕТ.** Экспорты (PDF/Excel/печать) — **вне этого среза**, отдельными задачами.

## Границы (важно проговорить)

**Лист показывает НАЧИСЛЕНО, а не «долг».** В системе нет сущности платежей/авансов, поэтому колонок
«оплачено» и «остаток» быть не может. Добавление платежей — изменение схемы и отдельное решение; сейчас
намеренно не делаем и не имитируем.

## Решения (зафиксированы с пользователем)

| Развилка | Выбор |
|---|---|
| Где живёт | **Новая вкладка на карточке фермера** `/reference/farmers/[id]` (`?tab=`), рядом с Главное/Контракты/Отгрузки/Остатки. Не новый экран → дизайн-раунд не нужен |
| Детализация | **Свод + раскрытие**: верхний уровень — строки контракта (культура · цена), каждая раскрывается в список партий |
| Период | **Сезон по умолчанию** + быстрые периоды (месяц · неделя · свой диапазон). Состояние — в URL |
| Базы веса | Строго по DOMAIN §1: **тонны выполнения — от ПРИНЯТОГО**, **деньги — от ОПЛАЧИВАЕМОГО** (принятый + доплата BR-33) |
| Расчёты | Переиспользовать существующее (`getContractExecution`, `computeAcceptedKg`, `computeSettlement`, агрегаты `server/farmers/card.ts`) — **новых формул не вводить** |

## Что уже есть (переиспользовать)

- `server/farmers/card.ts` — уже считает по строкам контракта `acceptedKg / targetKg / pct / surchargeKg /
  paidKg / costRub` с ПРАВИЛЬНЫМ комментарием о базах (`:45–53`), и построчные позиции с `acceptedKg` (`:212–236`).
- `server/contracts/execution.ts` — источник истины по выполнению и стоимости.
- `app/(app)/reference/farmers/[id]/_components/FarmerCardTabs.tsx` + панели — паттерн вкладок и таблиц.
- `server/shipments/workdays.ts` — сезон, ISO-недели, `todayLocalISO`/`FACTORY_TZ`.

### Чеклист ревью
1. Данные собираются из существующих расчётов; параллельных формул нет; `card.ts` не продублирован.
2. Базы веса не перепутаны (выполнение — принятый, деньги — оплачиваемый), в коде это прокомментировано.
3. Свод раскрывается в партии; корректировки BR-33 видны; секция «без привязки» присутствует при наличии.
4. Период в URL, дефолт — сезон; localStorage не используется.
5. Ничего не хранится; `requireRole()` на чтении.
6. Итоги сходятся с карточкой контракта и аналитикой; экспорта в срезе нет.
7. Тесты/lint/tsc/build зелёные.
