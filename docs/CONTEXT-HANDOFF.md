# ARCHITECTURAL DECISIONS
*(зафиксировано; не менять без обсуждения)*

- **Двухуровневый процесс PM↔Claude Code.** Причина: solo-dev с AI; PM держит живую модель и пишет проверяемые
  спеки, CC исполняет в среде с git/тестами. Нельзя: PM редактирует прод-код; фиксы — отдельными
  `PROMPTS-*-FIX.md`; новый экран → дизайн-спека → Claude Design → ревью → код-спека.
- **Спека требует ДИАГНОЗА до правки.** Причина: дважды гипотеза в ТЗ оказывалась перевёрнутой (строка контракта
  ломалась в simple-ветке, а не в calibre; «доля в культуре» считалась верно, врал рендер). Нельзя: чинить по
  предположению спеки, не подтвердив причину.
- **Балансы/стоимость/принятый вес/выполнение — вычисляются, не хранятся.** Причина: единый источник истины.
  Нельзя: кешированные суммы; вторая реализация формулы.
- **Четыре базы веса (DOMAIN §1).** Тара — плановый (на `sent`); ингредиент — фактический; выполнение контракта
  (тонны) — принятый; **деньги — ОПЛАЧИВАЕМЫЙ** (принятый + доплата BR-33). Брак — статистика. Нельзя путать.
- **Принятый ≠ оплачиваемый (BR-33).** `settlement_percent` — итоговый % к оплате от факта, разовый на акт;
  `к оплате = actual × settlement%`. Причина: оплату сверх принятого раньше проводили подделкой процентов
  категорий, что искажало аналитику качества. Нельзя: сливать тонны и деньги в одно число (`attributeAcceptedToLines`
  и `attributeSurchargeToLines` в `execution-core.ts` — ДВЕ РАЗНЫЕ карты, не объединять); включать доплату в
  выполнение; хранить оплачиваемый вес; давать правку процента не-админу.
- **BR-33 несовместим с «нестандарт со своей строкой контракта» (C3d-2).** Гейт оплаты в `execution.ts` —
  `contract_line_id != null`, поэтому непринятая категория со строкой оплачивается целиком, а доплата добавляет
  сверху → двойной счёт (пойман на проде). Комбинация запрещена валидацией. Нельзя: «складывать аккуратнее»
  вместо запрета.
- **Наборы дочерних строк сохраняются ДИФОМ по id, не `deleteMany+createMany`.** Причина: как только на строку
  появляются ссылки (`ShipmentItem.contract_line_id`), пересоздание падает о `onDelete: Restrict`, и правка
  контракта становится невозможной. Инвариант: **id строки стабилен при правке** — иначе привязки осиротеют.
  Нельзя: возвращать пересоздание; молча удалять строку со ссылками (нужна адресная ошибка с её названием).
- **Единый складской движок `StockMovement` (kind), нетто-дисциплина плеч, транзит-сентинелы −1/−2/−3.**
  Нельзя: новое плечо без нетто-гарда (гард «по существованию» ломает повторный цикл после отката — урок
  materials-fix); новые сентинелы.
- **Вес принятой позиции (`actual_weight_kg`) — read-only.** Причина: расход ингредиентов уже списан по этому
  весу; правка оставила бы леджер по старому весу. Менять — только через `revertAct`. Именно поэтому правка
  ПРОЦЕНТОВ акта без отката безопасна: она не трогает склад.
- **Завод — безлимитный внешний источник ИНГРЕДИЕНТОВ** (для тары остаётся полноценной локацией: тара
  возвращается). Причина: пользователю нужно «сколько забрал и кому передал», а не остаток бесконечного склада.
  Леджер не менялся — изменилось отображение. Нельзя: применять то же к таре.
- **Балансы агрегируются в БД (`prisma.groupBy`), две выборки (`to_*` плюсом, `from_*` минусом).** ОДНА функция
  агрегации с необязательным фильтром по items. Кэш (`unstable_cache`/TTL) сознательно НЕ вводился: после
  `groupBy` возвращаются десятки строк, а кэш добавил бы тихий стейл в остатки. Нельзя: `$queryRaw`; вторая
  свёртка; приведение `Decimal` к `number` по пути.
- **Порядок ячеек баланса (`cells`) — детерминированная сортировка, это КОНТРАКТ.** Порядок групп из БД не
  определён, а `server/farmers/card.ts` рендерит ячейки «как пришли». Нельзя: убирать сортировку как «лишнюю».
- **Prisma-free ядра для тестируемости:** `execution-core.ts`, `culture-agg.ts`, `ingredient-ledger.ts`,
  `board-filter.ts`, `accepted.ts`, `lines-diff.ts`. Причина: чистая часть расчётов должна импортироваться в
  vitest без БД. Нельзя: смешивать формулы с prisma-загрузчиком в одном модуле.
- **Единый `server/action-result.ts`: `ActionResult` + `authFail` + `failWithLog`.** Причина: `authFail` был в
  19 файлах. Все `catch` идут через `failWithLog` (`console.error`; отказ доступа НЕ логируется как ошибка).
  Текст `FORBIDDEN` унифицирован в «Нет прав» — снятие исключения `board/actions.ts` осознанно, не регресс.
- **Читающие server actions гардируются `requireRole()` БЕЗ ролей.** Причина: экспорт из `"use server"` —
  самостоятельный POST-эндпойнт в обход `(app)/layout.tsx`. Роли на чтениях НЕ ужесточать. Исключение —
  внутренние хелперы, принимающие `tx`.
- **Роль для клиентского UI — собственный `RoleProvider`/`useRole`, НЕ `useSession`.** Значение течёт пропом из
  серверного `app/layout.tsx` на каждом рендере, **без** `useState`/`useEffect`. Причина: `SessionProvider`
  кладёт проп в `useState`-инициализатор, из-за чего при клиентской навигации весь admin-UI пропадал (после F5
  работал — там SSR). Нельзя: возвращать чтение роли через `useSession`; заводить состояние в `RoleProvider`.
- **Сессия прокидывается из серверного `app/layout.tsx` в `SessionProvider` (`session={session}`).** Стоимость
  мала (JWT — `auth()` читает куку, без БД). Нельзя: `<SessionProvider>` без пропа; клиентский root layout.
- **`trustHost: true` — в `auth.config.ts`, НЕ в `auth.ts`.** Причина: `authConfig` потребляют ДВА инстанса
  NextAuth — `auth.ts` (node) и `proxy.ts` (edge). Нельзя: переносить флаг; тащить prisma/bcrypt в edge-конфиг.
- **Prisma 7: прямой коннект для CLI — `datasource.url` в `prisma.config.ts`** (ключ `directUrl` удалён).
  Рантайм — pooled `DATABASE_URL`. Нельзя: гнать миграции через pooled (ломает DDL-локи).
- **«Сегодня» и ГРАНИЦЫ ПЕРИОДОВ — в `FACTORY_TZ` (`Europe/Moscow`), хранение дат — UTC-полночь.** Причина:
  UTC-«сегодня» до 03:00 отдаёт вчера; правка в 00:30 МСК выпадала из фильтра своего дня. Клиентские места
  тоже обязаны звать `todayLocalISO()`. Нельзя: трогать `parseDateUTC`.
- **Отправление = прибытие − 2 КАЛЕНДАРНЫХ дня; рабочие дни завода ограничивают только ПРИБЫТИЕ.** Причина:
  машину грузит фермер, завод не участвует. Нельзя: считать отправление рабочими днями (давало пн → пт).
- **Порядок категорий калибра — размерный** (`compareCalibreRanges`: `min_cm` ASC, затем `max_cm`; безразмерные
  в конец по `id`). Причина: сортировка по доле делала порядок зависимым от данных. Поля `sort_order` в схеме
  нет и не нужно. Нельзя: вторая сортировка категорий.
- **Печать — print-CSS, bare-роуты `app/print/*`**, PDF через браузерное «Сохранить как PDF».
  Сводка/План — **landscape**, остальные листы — **portrait**. Общий каркас — `PrintSheet`. Нельзя: серверные
  PDF-библиотеки; `@media print` поверх интерактивных экранов; печатать деньги в натуральных листах.
- **Экспорт Excel — клиентский SheetJS через один хелпер `lib/xlsx-export`.** Нельзя: вторая точка SheetJS;
  **числа выгружать строками** (только числами, иначе Excel не считает).
- **Аналитика по культуре — отдельный экран `/analytics/culture/[id]`**, % брака графиком по неделям,
  **выполнение у фермера без контракта = «—»** (не 0 — чтобы не путать «нет контракта» с «мало принял»).
  Нельзя: деньги-KPI на этом экране; сравнение год-к-году (нет истории).
- **Состояние вида/недели/сезона/фильтров — в URL, не localStorage.** Причина: шарабельность, воспроизводимость.
- **Палитра культур `CULTURE_PALETTE` (12 цветов); `Culture.color` — hex.** Причина: произвольный hex давал
  неразличимые и «статусные» цвета. Нельзя: хардкодить цвета мимо константы; ломать off-palette-культуры (их
  цвет — «свой цвет»); **запрещать дубли цветов** — только предупреждать.
- **FK-Select: фактически привязанное значение ВСЕГДА присутствует в опциях** (неактивное · из другого сезона ·
  вне выборки), помечается. Причина: селект с валидным `value`, но без опции, рисует плейсхолдер и показывает
  «не привязано» при живой привязке (реальный дефект acceptance-ux-1). Нельзя: фильтровать опции так, чтобы
  текущее значение выпало.
- **`FilterCombo` — общий компонент: счётчик считается по пересечению `selected` с известными `options`,
  сам `selected` компонент НЕ фильтрует.** Причина: битый id в URL поднимал счётчик без отмеченной строки;
  фильтрация — ответственность вызывающего (компонент используют 4+ экрана).
- **Тесты — co-located `*.test.ts` рядом с модулем; фиксируют ИНВАРИАНТЫ, не покрытие.** CI гоняет
  `lint + typecheck + test`; **`npm run build` в CI НЕ запускать** (в нём `migrate deploy`). Нельзя: править
  тест «под код» при расхождении — это повод для разбора.
- **Verify-скрипты и `scripts/_stubs/` — часть репозитория.** Стабы подменяются per-script через
  `registerHooks`. Нельзя: заводить стабы глобальным алиасом (`_stubs/auth.ts` пропускает любого → дыра в RBAC).
- **Водитель и ТК — не учётные величины (BR-34).** Меняются точечно на любом статусе, admin, без отката;
  снятие водителя на `sent+` невозможно. ТК приезжает вместе с водителем и меняется вслед за ним, в том числе
  задним числом на принятых рейсах — снимка в акте нет. Нельзя: ослаблять гард «водитель обязателен при
  отправке»; заводить второй путь правки водителя на `planned` (там обычная форма).
- **Расчётный лист = НАЧИСЛЕНО.** Сущности платежей/авансов в системе нет, поэтому «оплачено»/«долг» не
  показываем и не имитируем. Нельзя: рисовать колонки, за которыми нет данных.
- **Экспорты листа строятся из УЖЕ ПОСЧИТАННОГО `FarmerSettlement`** — печать зовёт тот же
  `getFarmerSettlement`, Excel строится из пропа экрана. Причина: инвариант «печать/экспорт — тем же чистым
  фильтром, что экран». Ссылка печати собирается из НОРМАЛИЗОВАННОГО `period`, не из сырого URL (иначе битый
  `?from=` уезжает на лист). Нельзя: вторая выборка; формулы в `page.tsx`; PDF-библиотеки (PDF = браузерное
  «Сохранить как PDF»); вторая точка SheetJS — `downloadXlsxBook` единственная реализация записи,
  `downloadXlsx` её обёртка.
- **Факт позиции (`actual_weight_kg`) — свойство ПОЗИЦИИ, а не акта.** `SheetItem.actualKg` обязателен и
  заполняется независимо от наличия акта; `exec.actualKg` (Decimal) остаётся входом движка расчётов и с ним
  не сливается. Причина: поле было объявлено в `SettlementPending`, но наполнялось литералом `null` — колонка
  «Факт, кг» стояла пустой и на печати, и в Excel. Нельзя: делать поле опциональным (следующий маппер забудет);
  суммировать факт по ожидающим (перевеска позиционная — Σ занизила бы факт).
- **Числа выводятся только через `lib/format.ts`** (`fmtTons`/`fmtInt`/`fmtPct1`/`fmtPrice`/`fmtPercent`).
  Причина: цена рендерилась сырым `number`, печатный лист завёл локальный `fmtDec`, и экран с листом
  разошлись на первом дробном значении. Нельзя: локальные форматтеры в компонентах. Исключение — xlsx:
  там числа кладутся числами.
- **Данные: dev vs прод.** Dev-проект Neon одноразовый; **прод-данные ценные, миграции обязаны быть
  data-preserving**, деструктив — только с `pg_dump` и ревью. Правило dev-вайпа к проду НЕ применять.

# ACTIVE RISKS

- **Neon free-план:** лимиты НА ПРОЕКТ (100 CU-часов, 0.5 GB, 5 GB egress); при исчерпании compute
  **суспендится до следующего месяца**. PITR всего **6 часов**, scheduled-снапшотов нет →
  **свой `pg_dump` обязателен** (команды и правила — `PROD-DEPLOY.md` §8). Бэкап, который не восстанавливали,
  не считается бэкапом.
- **`xlsx 0.18.5`** — Prototype Pollution + ReDoS, фикса на npm нет. Использование write-only (`lib/xlsx-export`),
  чужие файлы не парсятся → принятый долг. Вернуться, когда понадобится ЧТЕНИЕ Excel (импорт норм/контрактов).
- **Свежесть роли в JWT (вторая половина П-4)** — роль читается из токена, из БД не перечитывается.
  При одном пользователе-админе риска нет; вернуться при появлении операторов.
- **`ChangeLog` без индекса по `timestamp`** — журнал всегда сортирует `timestamp DESC`. На ~900 записях
  незаметно; при замедлении — `@@index([timestamp])` или keyset по `id DESC`.
- **Печать профиля культуры не имеет пустого состояния:** `?suppliers=` с фермером без позиций даёт лист с
  нулями и графиком из одного плана. С экрана такая ссылка не строится, только руками через URL.
- **Факт. ср. вес рейса:** частично перевешенная машина учитывается Σ только взвешенных позиций (занижает →
  оценка «осталось ~N машин» консервативнее). Осознанный компромисс (DOMAIN §5).
- **`is_accepted` калибра — из живой схемы, не снимок акта:** правка схемы калибров задним числом меняет историю.
- **Отрицательный баланс фермера** (расход/отметка раньше прибытия) — допустим осознанно.
- **`prisma migrate status` из среды агента** может не достучаться до Neon — проверять вручную.
- **Снимков в актах нет — история подвижна:** акт берёт имя водителя и ТК живьём через
  `shipment.driver.transportCompany` (`server/acceptance/act.ts:169–170`), как и `is_accepted` калибра берётся
  из живой схемы. Смена водителя задним числом меняет то, что показывают акт и печатные формы. Принято
  осознанно (см. BR-34): след остаётся в ChangeLog.
